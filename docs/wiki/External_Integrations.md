# AI 임베딩 파이프라인 최적화

도서 검색의 정확도를 높이기 위해 도서 정보를 벡터 데이터로 변환하여 Elasticsearch에 저장하는 과정에서 발생한 기술적 문제와 해결 방안을 기술합니다.

## 1. 개요
*   **목적**: 도서 제목, 저자, 카테고리, 태그, 설명을 결합한 텍스트를 1024차원의 벡터로 변환(Embedding).
*   **모델**: `bge-m3` (Ollama를 통해 서빙).
*   **활용**: Elasticsearch의 k-NN(k-Nearest Neighbors) 검색에 적용.

## 2. 기술적 도전 및 해결 전략

외부 API 호출(Ollama)이 포함된 임베딩 작업은 배치 처리 속도를 저하시키고 DB 커넥션 점유 시간을 길게 만드는 병목 지점이었습니다. 이를 해결하기 위해 다음과 같은 최적화 기법을 적용했습니다.

### 2.1. 작업 단계 분리 (Step Separation)
*   **문제**: 도서 정보 업데이트와 임베딩 생성을 하나의 트랜잭션에서 처리할 경우, API 응답을 기다리는 동안 DB Row Lock을 장기간 보유하게 됨.
*   **해결**: 정보 보강(Enrichment)과 임베딩(Embedding) 단계를 별도의 Step으로 분리.
*   **효과**: 데이터 갱신 트랜잭션을 먼저 완료한 뒤, 별도의 독립적인 트랜잭션에서 임베딩 작업을 수행하여 DB 락 점유 시간을 최소화.

### 2.2. 처리 효율성 개선 (Bulk & Fetch Strategy)
*   **Bulk Operations**: 개별 건마다 DB/ES를 업데이트하지 않고, Writer에서 `JdbcTemplate`의 `batchUpdate`와 Elasticsearch의 `Bulk API`를 사용하여 처리 결과를 일괄 갱신함으로써 네트워크 오버헤드와 트랜잭션 빈도를 감소시킴.
*   **Fetch Strategy**: Reader에서 `JOIN FETCH`를 사용하여 임베딩 텍스트 생성에 필요한 모든 연관 데이터(저자, 태그 등)를 한 번에 조회. 처리 과정에서의 추가 쿼리 발생(N+1 문제)을 차단.
